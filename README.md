# 学生成绩管理系统

一个用 C++ 写的命令行成绩管理工具，外加一个可视化的网页看板。

网页支持两种模式：
- **静态模式**：读 C++ 导出的 `data.js`，只能看，双击就能打开（GitHub Pages 上就是这个模式）
- **后端模式**：启动 Python 本地服务后，网页可以直接增删改学生，数据实时写进 `students.txt`

## 架构

```
                ┌─────────────────┐
                │  C++ 程序        │  录入/统计/导出（离线）
                └────────┬────────┘
                         │ 写
                    students.txt
                         │ 读写
                ┌────────▼────────┐
                │ Python 后端      │  /api/students（增删改查）
                └────────┬────────┘
                         │ HTTP + JSON
                ┌────────▼────────┐
                │ 网页看板          │  榜单 / 图表 / 表单
                └─────────────────┘
```

网页启动时会先试着请求 `/api/students`：
- **成功** → 进入后端模式，显示「已连接后端 · 数据可实时读写」，出现添加表单和编辑/删除按钮
- **失败** → 退回静态模式，读 `data.js`，显示「静态数据 · 只读」

这样同一份网页，本地起服务能演示真后端，挂到 GitHub Pages 上又能当静态展示页。

## 功能

**C++ 端**
- 录入学生（学号、姓名、三门课成绩），自动查重
- 查看全部、总排名（按平均分）
- **单科排名**（选任意一科单独排）
- **按分数筛选**（例：数学 ≥ 80 的有谁）
- **修改学生信息**（姓名 + 各科成绩，不想改的项输 `-1` 跳过）
- 删除学生（带确认）
- 班级统计：平均分、最高/最低、全科及格率、各科平均分、**分数区间分布（优秀/良好/中等/及格/不及格）**
- **自动存档**：数据写在 `students.txt`，关掉程序下次打开还在
- 导出 `grades.csv`（Excel 可打开）和 `web/data.js`（网页读取）

**网页端**
- 概览数字卡片（人数、班级平均分、最高总分、及格率）
- **成绩前十榜**：卡片式展示，带照片
- **单科排名**：点科目标签切换，看这一科谁最高
- **等级分布**：优秀 / 良好 / 中等 / 及格 / 不及格，条形长度对应人数占比
- 成绩明细表（前三名用颜色标记）
- 平均分对比条形图
- **学生照片**：两种办法——① 把照片命名成 `学号.jpg`（或 `.png`）放进 `web/photos/`；② 启动后端后，点明细表每行的「照片」按钮，直接从电脑选图上传。没照片的显示姓氏首字的彩色头像
- **在线增删改**：启动后端后，页面上直接添加 / 编辑 / 删除学生，改动立刻写进 `students.txt`

## 运行方法

### 方式一：只用 C++（离线）

**1. 编译**

双击 `build.bat`。它会调用 Visual Studio 的编译环境，成功后生成 `grade.exe`。

**2. 运行**

双击 `run.bat`，或直接双击 `grade.exe`。

**3. 看网页**

菜单里选 `9` 导出数据，然后双击 `web/index.html`。

### 方式二：启动后端（网页可编辑）

**1. 启动服务**

双击 `server/启动服务.bat`，会弹出一个黑窗口，显示：

```
打开地址：http://localhost:8000
停止服务：按 Ctrl + C
```

**2. 打开网页**

浏览器访问 **http://localhost:8000**（不要双击 html 文件，那样连不上后端）

**3. 直接操作**

页面顶部出现「添加学生」表单，每行末尾出现「编辑」「删除」按钮，改完立刻写进 `students.txt`。

**注意**：这个黑窗口不能关，关了后端就停了。要停服务按 `Ctrl + C`。

## 后端接口

| 方法 | 路径 | 作用 | 成功状态码 |
|---|---|---|---|
| GET | `/api/students` | 取全部学生 | 200 |
| POST | `/api/students` | 添加学生 | 201（学号重复返回 409） |
| PUT | `/api/students/<学号>` | 修改姓名/成绩 | 200 |
| DELETE | `/api/students/<学号>` | 删除学生 | 200 |
| POST | `/api/photos/<学号>` | 上传学生照片 | 201 |

请求和返回都是 JSON，例如添加：

```json
{ "id": "2026013", "name": "新同学", "scores": [88, 90, 85] }
```

照片上传不走 JSON，直接发图片的原始二进制（前端用 `<input type="file">` 拿到文件后原样 POST）：

```
Content-Type: image/jpeg  或  image/png
请求体：图片文件本身（不超过 3MB）
```

服务端用 `Content-Type` 判断存成 `.jpg` 还是 `.png`，并且会先删掉这个学号的旧照片，
所以一个人只会有一张。成功返回：

```json
{ "ok": true, "file": "2026001.jpg", "size": 142565 }
```

出错情况：学号不存在 → 404；不是 jpg/png → 400；空数据 → 400；超过 3MB → 413。

上传成功后前端会给图片地址加时间戳（`photos/2026001.jpg?v=1700000000000`），
否则浏览器会一直显示缓存里的旧照片——这是实际开发里很常见的坑。

## 几个使用说明

**改姓名**：菜单 `6`，输学号 → 新姓名（输 `-` 跳过）→ 各科成绩（输 `-1` 跳过）。
学号不开放修改：它既是查找的钥匙，也是网页找照片的文件名。真要换学号，删掉重新添加。

**改学号以外的信息**：都走菜单 `6`。

**照片命名**：手动放照片时用 `photos/学号.jpg`，改名时小心 Windows 隐藏扩展名，别弄成 `2026001.jpg.jpg`。
走网页「照片」按钮上传就不用管这些，后端会自动命名成 `学号.jpg` 或 `学号.png`。

## 三个设计说明

**为什么网页读的是 `data.js` 而不是 `data.json`**

浏览器直接用 `file://` 打开网页时，读取 `.json` 会被同源策略拦住（CORS），
而 `<script src="data.js">` 属于加载脚本，不受这条限制。
所以让 C++ 直接生成一个 `var STUDENTS = [...]` 的 js 文件，是不需要起服务器的最简方案。

**为什么命令行表格不用 `setw` 对齐**

一个中文字符的显示宽度是英文字母的两倍，`setw` 按字符数补空格永远对不齐。
所以改成「一行一个学生」的标签式输出，中英混排都不会歪。

**为什么要写输入保护**

用户在输入数字的地方打了字母，`cin` 会进入错误状态，
之后所有输入全部失效、程序陷入死循环。
所以读数字统一走 `readInt` / `readDouble`，失败就 `clear()` + `ignore()` 兜底。

## 技术点

- `struct` 组织数据，`vector` 存多个学生
- `sort` + lambda 表达式做排名
- `ofstream` / `ifstream` 文件读写（存档 + 导出）
- 输入流状态处理（`cin.clear()` / `cin.ignore()`）
- **HTTP 服务端**：Python 标准库 `http.server`，自己解析路径和 JSON，不用任何框架
- **REST 风格接口**：GET / POST / PUT / DELETE 对应查 / 增 / 改 / 删
- **前端异步请求**：`fetch` 取数据，改完重新拉取刷新页面
- **优雅降级**：接口连不上就退回读静态文件，同一份网页两种用法
- 跨语言数据交换：C++ 与 Python 共用同一个 `students.txt`
